# set verbose_ctcp

## Synopsis

```text
/set verbose_ctcp [on|off|toggle]
```

Provided by the bundled `builtins` script. Default: `on` when that script initializes the setting. With no argument, [set](../commands/set.md) displays the current value.

## Description

When on, permits the ordinary informational message for CTCP requests that reach the [on ctcp](../on/ctcp.md) display hook. When off, the supplied script handler suppresses that hook's default request display. This provides a way to hide routine CTCP request notices without disabling the request handlers or their replies.

The setting is implemented by a script-defined boolean and a conditional `ctcp` hook, not a C variable read by the CTCP parser. Turning it on does not force every request to be displayed: earlier [ctcp_request](../on/ctcp_request.md) handling, CTCP handler flags, or other hooks can bypass or replace the ordinary display.

## Scope and interactions

This controls the default request notice, not all CTCP-related output. Reply displays use [on ctcp_reply](../on/ctcp_reply.md) separately, and actions or other specially handled CTCPs can follow their own display paths. Script-generated messages are not automatically suppressed by this boolean.

The CTCP request handler runs before the ordinary request display stage. Suppressing that display therefore does not cancel a reply already generated by the handler or stop the client from processing the request. Conversely, scripts replacing or removing the supplied `ctcp` hook can change or eliminate this setting's effect.

Changing the value affects later eligible requests, does not erase existing output, and does not send an IRC request. Without the defining script and its hook, the setting supplies no built-in verbosity policy.

## Example

Hide ordinary CTCP request notices:

```text
/set verbose_ctcp off
```

Restore permission for the normal notices with `/set verbose_ctcp on`. Other hooks and specialized handlers still determine which requests actually reach the default display.
