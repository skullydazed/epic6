# CTCP PING

## Synopsis

```irc
/ctcp <target> ping <seconds> <microseconds>
```

## Description

CTCP `PING` supplies the underlying protocol for [`ping`](../commands/ping.md). Prefer `/ping <target>` for ordinary use; it fills in the timestamp automatically. EPIC's timestamp has two fields: seconds since the Unix epoch and a microsecond fraction.

A supporting recipient echoes the argument text. The supplied EPIC6 [CTCP script](../../script/ctcp), loaded by [script/builtins](../../script/builtins), provides both automatic echoing and elapsed-time interpretation of replies. Its reply handler subtracts the returned timestamp from the current time and substitutes `<elapsed> seconds` for display through [`on ctcp_reply`](../on/ctcp_reply.md).

The result estimates round-trip delay through the IRC network and remote client, including any processing or throttling delays. It is separate from IRC server `PING`/`PONG` messages. A reply is not guaranteed, and the script does not check returned timestamps against a saved outstanding request.

The current reply script leaves the original arguments unchanged when either timestamp field evaluates as false or the calculated delay is negative. Thus a zero microsecond field does not receive the normal elapsed-time replacement. Its calculation uses wall-clock time, so clock adjustments can affect the result. Automatic replies are subject to the normal CTCP reply throttle.

## Example

```irc
/ping john
```

For explicit use in a script, the equivalent timestamped request is `ctcp john ping $utime()`. The generic [`ctcp`](../commands/ctcp.md) command does not insert a timestamp on its own.
