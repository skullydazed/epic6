# CTCP USERINFO

## Synopsis

```irc
/ctcp <target> userinfo
```

## Description

Ask another client for its user-supplied information text. An EPIC6 responder returns its [`user_information`](../set/user_information.md) setting, which can contain whatever text the user chooses. Other clients may use different settings or decline to answer. See [`ctcp`](../commands/ctcp.md).

EPIC6 supplies the responder in [script/ctcp](../../script/ctcp), loaded by [script/builtins](../../script/builtins). It ignores additional request arguments and sends the current setting value. The compiled default is `EPIC6 -- Did we get lost again?`. An unset or empty value produces a reply without argument text; it does not disable the handler.

Received replies normally pass through [`on ctcp_reply`](../on/ctcp_reply.md) and display as `CTCP USERINFO reply from sender: text`. Request hooks, inactive CTCP registration, and outgoing reply throttling can prevent a response. Encoding conversion and message-length limits apply to the transmitted text.

## Examples

```irc
/ctcp john userinfo
/set user_information Ask me about EPIC scripting.
```

The first requests another client's information. The second changes what your own supplied responder returns.
