# CTCP VERSION

## Synopsis

```irc
/ctcp <target> version
```

## Description

Ask another IRC client which client and version it is using. The response can be customized or falsified by that client or its scripts; it is not verified software identification. A reply is not guaranteed. See [`ctcp`](../commands/ctcp.md).

EPIC6 supplies its responder in [script/ctcp](../../script/ctcp), loaded by [script/builtins](../../script/builtins). It ignores additional request arguments and constructs this reply:

```text
ircII <client-version> - <client-information>
```

`<client-version>` is `$J`, the compiled `irc_version` string. `<client-information>` is the current [`client_information`](../set/client_information.md) setting, initialized from the build's `IRCII_COMMENT`. Contrary to the original documentation, this handler does not independently obtain or append the operating system name and version. Such information appears only if the configured text or a customized handler includes it.

Received replies normally pass through [`on ctcp_reply`](../on/ctcp_reply.md) and display as `CTCP VERSION reply from sender: reply-text`. Request hooks, inactive CTCP registration, and outgoing reply throttling can prevent automatic responses.

## Examples

```irc
/ctcp john version
/set client_information Running my own scripts.
```

The first requests John's client identification. The second changes the final portion of your own supplied responder's reply.
