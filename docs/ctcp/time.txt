# CTCP TIME

## Synopsis

```irc
/ctcp <target> time
```

## Description

Ask another IRC client for its local date and time. This differs from the [`time`](../commands/time.md) command, which queries an IRC server. Not every client supports or permits this request, and a reply is not guaranteed. See [`ctcp`](../commands/ctcp.md).

EPIC6's responder is supplied by [script/ctcp](../../script/ctcp), loaded by [script/builtins](../../script/builtins). It ignores additional request arguments and replies with `$stime($time())`: the current client-host clock formatted in its local timezone and locale. The answer reflects the remote host's configuration and clock accuracy.

Replies normally pass through [`on ctcp_reply`](../on/ctcp_reply.md) and display as `CTCP TIME reply from sender: date-and-time`. Request hooks or inactive CTCP registration can prevent a response. The C sender retains a reply-throttling branch, but [`no_ctcp_flood`](../disambiguation/set_no_ctcp_flood.md) is not a registered setting. The branch updates its timestamp only when dropping replies; it does not establish a supported or reliable reply-rate limit.

## Example

```irc
/ctcp john time
```
