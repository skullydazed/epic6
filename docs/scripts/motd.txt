# motd script

## Synopsis

```irc
/load motd
```

## Description

This script supplies a local installation's message of the day, separate from the IRC server's [`motd`](../commands/motd.md) command. The site administrator provides an `ircII.motd` file under the directory returned by `$irclib()`.

When loaded, the script compares that file's modification time with the marker `~/.ircII.motd`. If the source timestamp is nonzero and newer, it displays the file through the [`less`](less.md) pager and launches `exec touch ~/.ircII.motd`. The marker's modification time matters; its contents do not. `ftime()` returns empty when a file cannot be examined, so a missing marker normally allows an existing newer source to display.

This check happens only when the script is loaded. To check at startup, explicitly load it from a personal startup file or the site's local configuration. The supplied `global` startup file can load a `local` file, but neither it nor `local.examp` automatically loads `motd`. The original claim that every later startup displays a changed file therefore assumes such configuration.

## Requirements and limits

The script loads `less` itself. That pager needs the `winnum()` and `winsize()` wrappers supplied by [`builtins`](builtins.md), and its own retained implementation limitations apply. The external `touch` command must be available through the configured exec shell, and the user must be able to update the home-directory marker.

The marker is updated after the pager's initial call returns, potentially before later pages are read. It records an attempt to present the file, not proof that the user read it completely. The wrapper does not check pager or marker-command success. Only modification times are compared: changed contents with an unchanged or older timestamp are not detected. The script also assigns ordinary variables named `date` and `fdate`.
