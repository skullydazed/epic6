# DCC GET (removed)

## Former synopsis

```irc
/dcc get [=]<nick> <file> [<file> ...]
/dcc get [=]<nick> <file> [<file> ...] /directory
/dcc get [=]<nick> <offered-file> <alternate-local-name>
/dcc get [=]<nick>
```

## Current status

EPIC6 has removed the built-in `/dcc` command and DCC transfer implementation. These former forms cannot accept offers or download files in the current client. Retained scripts referring to DCC do not restore the removed primitives.

## Historical behavior

DCC Get accepted a file offered by another client's DCC Send and opened a direct transfer connection. When the offer arrived through DCC Chat, the peer was selected by that chat's local name, including the `=` prefix.

The former filename selector accepted exact offered names, the special `*` selector for all offers from a peer, or no filename. It did not accept arbitrary wildcard patterns. Two filename arguments, one offered and one not offered, could select the offered file and give it an alternate local name. A final directory argument selected the download directory for the chosen files.

The original document contradicts itself about a nickname with no filename: one paragraph says it accepts the oldest pending offer, while another says it accepts all offers. That distinction cannot be checked against the current source because the implementation is gone. The explicit `*` example below was documented as the all-offers form; neither form is available in EPIC6.

The receiving host needed to establish an outbound connection, and the offering host needed to accept it. Firewalls, NAT, or routing restrictions could prevent that connection. Receiving a file directly also exposed the recipient's endpoint address to the sender, even when the IRC network hid it.

The original implementation documentation cautioned that received files and handshake arguments could be malicious, and reported that a leading dot in an offered filename was changed to an underscore to avoid receiving dotfiles under their original names. Those were properties and concerns of the removed transfer path, not current EPIC6 filename handling.

## Historical examples

These commands identify obsolete configurations and are not supported EPIC6 operations:

```irc
/dcc get bob
/dcc get DCCbot *
```

The second was the documented explicit form for accepting all offers from DCCbot. The original description of the first is inconsistent as noted above.
