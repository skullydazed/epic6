# DCC RESUME (removed)

## Former synopsis

```irc
/dcc resume [=]<nick> <file>
```

## Current status

EPIC6 has removed the built-in DCC command and transfer implementation. It cannot resume a transfer through this interface. The former `MIRC_BROKEN_DCC_RESUME` setting and compile-time flag are also absent; old settings or build-option letters do not restore this feature.

## Historical behavior

DCC Resume attempted to continue an incomplete [DCC Get](ctcp_get.txt) transfer using a partially downloaded local file, instead of starting the download again. The sending and receiving clients had to support the same restart negotiation.

The original documentation required the `MIRC_BROKEN_DCC_RESUME` compile-time option and the corresponding runtime setting. It reported that the compile-time option was enabled by default, while the runtime setting defaulted off, and that the letter `i` in `$info(o)` identified that historical build option. These instructions describe the removed implementation and are not current EPIC6 configuration steps.

The original document also warned about protocol compatibility, possible negotiation loops, and transfer failure with unsupported peers. Its advice was to confirm the sender's support before attempting a resume; a failed attempt could require restarting the transfer. These historical cautions do not imply a supported transfer path remains in EPIC6.

## Historical example

This identifies an obsolete operation and is not a supported EPIC6 command:

```irc
/dcc resume joebob somebigfile
```

## History

The original documentation records that DCC Resume first appeared in EPIC4pre1.049. Its DokuWiki revision identifier was `dcc_resume.txt,v 1.6 2006/08/01 02:45:08 sthalik Exp`.
