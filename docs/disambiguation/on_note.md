# on note (removed)

## Former synopsis

```text
/on [<noise>]note "<pattern>" { <commands> }
```

## Description

The `note` event formerly reported receipt of an IRC note and let scripts customize its display. EPIC6 has removed this named hook and the former incoming note-processing stage. It no longer generates a `note` event or supplies its historical message fields.

## Former parameters

| Parameter | Former meaning |
| --- | --- |
| `$0` | Sender's nickname. |
| `$1` | Message send time, historically described as accurate within about 60 seconds. |
| `$2-` | Message text. |

These describe the removed interface, not arguments generated by EPIC6. The former example that reformatted a note's sender, time, and text cannot run through this hook.

## Compatibility

Attempting to register `/on note ...` is rejected with `No such ON function: NOTE`. There is no built-in note-display action to customize or suppress through this event.

The separate [note](../commands/note.md) command remains in the command table as a generic server-command sender. It forwards its arguments to the IRC server; availability and responses depend on that server. Sending `/note` does not recreate the removed receive hook, local note parsing, or its timestamp fields.

Scripts integrating a server's note or service facility must handle the replies it actually sends through appropriate active message or numeric events. There is no universal replacement event with the former `note` arguments.
