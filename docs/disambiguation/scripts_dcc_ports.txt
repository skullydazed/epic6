# dcc_ports script (obsolete)

## Former interface

```irc
/load dcc_ports
/set dcc_port_min 1024
/set dcc_port_max 65535
```

## Description

The script formerly selected ports for outgoing DCC Chat and DCC Send offers, as though a `-p` port had been supplied to the DCC command. EPIC6 has removed `/dcc` and `$dccctl()`, so loading the retained script does not restore transfer support or control DCC listening ports.

The retained script loads [`addset`](../scripts/addset.md), defines integer settings `dcc_port_min` and `dcc_port_max`, and initializes them to 1024 and 65535. Changing either value regenerates `dcc_ports.picklist` using `jot()`. The picker removes and returns its first number, regenerating the list when empty. With an ascending range, the sequence includes both endpoints and advances one port at a time before wrapping.

The original document described selecting the next open port. The script itself only selects numbers; it does not test, open, or reserve a port. Its former integration installed the picker through `dccctl(DEFAULT_PORT ...)`, which is absent from the current function table. No DCC subsystem consumes this list in EPIC6.

These script-defined settings do not select IRC server connection ports. The script also does not validate endpoints against TCP port limits or reject a reversed range; `jot()` can generate a descending sequence instead.
