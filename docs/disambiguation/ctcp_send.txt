# DCC SEND (removed)

## Former synopsis

```irc
/dcc send [=]<nick> [-p <port>] <file> [<file> ...]
```

## Current status

EPIC6 has removed the built-in DCC command and transfer implementation. This former command cannot offer files or start a direct transfer in the current client. Retained scripts that call DCC do not restore those primitives.

## Historical behavior

DCC Send offered one or more files to another client. The transfer began only after the recipient accepted the offer and opened the direct connection. The optional `-p <port>` selected the port for that connection.

An offer could be sent over an existing [DCC Chat](ctcp_chat.txt) connection by prefixing its local peer name with `=`. This bypassed IRC routing for negotiation; the original document's statement that it was faster was not a guarantee of transfer speed.

An outgoing offer exposed the client's endpoint IP address to the recipient, even when the IRC network hid it behind a cloaked hostname. That address disclosure was part of the historical direct-transfer negotiation.

## Historical examples

These identify obsolete configurations and are not supported EPIC6 operations:

```irc
/dcc send joebob somefile
/dcc send joebob -p 1234 somefile
```

The second selected port 1234 for the offered transfer.
