# stop_irc binding (removed)

## Former synopsis

```irc
/bind <key> stop_irc
```

## Description

In older EPIC versions, this binding sent the client `SIGTSTP`, suspending it and returning control to its shell. This allowed users to run other shell commands while leaving the IRC client in the background as a stopped job.

EPIC6 does not implement or register the built-in `stop_irc` action. Attempting to bind a valid key sequence to it in an unmodified session reports `No such function stop_irc` and leaves the binding unchanged. Control-Z is not assigned to this action by the default keymap, and fullscreen terminal initialization disables the terminal driver's suspend character where supported.

If a client is stopped by an external mechanism, a job-control shell can normally resume its foreground job with `fg`. That shell operation is separate from EPIC's removed keybinding. While stopped, the client cannot service its IRC connections, so an extended suspension can cause server timeouts and disconnections.

See [`bind`](../commands/bind.md) for supported binding operations.

## Source references

- [source/keys.c](../../source/keys.c): `init_binds()` and `init_keys()` omit `STOP_IRC`; `bind_compressed_string()` rejects unknown actions before modifying bindings.
- [source/term.c](../../source/term.c): fullscreen terminal initialization disables `VSUSP`/`VDSUSP` where available; `term_cont()` restores terminal handling after continuation.
- [source/irc.c](../../source/irc.c): installs the `SIGCONT` handler for terminal restoration.
