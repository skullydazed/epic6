# on dcc_list (removed)

## Former synopsis

```text
/on [<noise>]dcc_list "<pattern>" { <commands> }
```

## Description

The `dcc_list` event formerly ran for lines produced by [dcc list](ctcp_list.md), or by `/dcc` without a subcommand. Scripts used it to inspect open DCC connections or customize their listing. `$0` identified the start banner as `Start` and the end of the listing as `end`; connection rows supplied the fields below.

EPIC6 has removed the DCC implementation, its session listing, and this named hook. There are no built-in connection rows, banner events, or list-item output to intercept or suppress.

## Former connection-row parameters

| Parameter | Former meaning |
| --- | --- |
| `$0` | DCC connection type. |
| `$1` | Reserved encryption indicator, documented as `1` for on and `0` for off. |
| `$2` | Peer nickname. |
| `$3` | Connection status. |
| `$4` | Establishment time in [time](../functions/time.md) format, or `0` if not connected. |
| `$5` | File-transfer size, or `0` when not applicable. |
| `$6` | Bytes transferred, or `0` if not connected. |
| `$7` | Description, usually the full filename. |

These describe the removed interface, not arguments generated by EPIC6. Allowing default handling formerly displayed the corresponding list item.

## Compatibility

Attempting to register `/on dcc_list ...` is rejected with `No such ON function: DCC_LIST`. The former `/dcc list` command is unavailable too. A retained hook reference in `script/builtins` does not restore either feature.

Scripts implementing their own transfers must maintain their own connection inventory and progress display. There is no built-in replacement event with these fields. Former handlers that calculated transfer progress from the size and byte counts cannot run through this hook in EPIC6.
