# on mail (removed)

## Former synopsis

```text
/on [<noise>]mail "<pattern>" { <commands> }
```

## Description

The `mail` event formerly ran when the client's built-in local mailbox checker detected new email. It depended on the former nonzero `mail` setting and let scripts customize the new-mail notification.

EPIC6 has removed that built-in checker and this named hook. Although mailbox checking has returned as a script, the supplied checker does not generate `on mail`. There is no current `mail` event through which to suppress or replace its new-mail announcement.

## Former parameters

| Parameter | Former meaning |
| --- | --- |
| `$0` | Number of new messages. |
| `$1` | Total messages in the mailbox. |

These describe the removed interface, not arguments generated by EPIC6. The former example that adjusted singular and plural notification wording cannot run through this hook. The old limitation concerning extended output when `mail` was `2` no longer describes the current checker, whose script-defined `mail` setting is boolean.

## Current script behavior

`script/mail` loads `mail.py` through Python support. That script defines its own `mail`, `mail_interval`, and `mail_status_format` settings, periodically checks supported local mailbox sources, directly prints `There are N new email(s), T total` when new messages are detected, and updates [status_mail](../set/status_mail.md). Its `mail_status_format` uses `{new}` and `{cur}` fields for status text. This is script-provided behavior, not a restored C hook.

Attempting to register `/on mail ...` is rejected with `No such ON function: MAIL`, even when the checker script is loaded. Scripts requiring a custom notification event must implement that integration themselves. Mail checking is local behavior and does not send an IRC request.
